# Music Score Digitizer v3 — 扫描乐谱数字化

> v3 变更背景：《小天鹅舞曲》（两页笙谱）全 AI 逐像素转谱实测消耗过大
> （ASCII 图刷屏 + 试错探针 + 规则重推导）。v3 把流程改为
> **"机器打草稿 → 代码答是非题 → AI 只啃低置信项"**，同类谱成本目标压到 1/5。

## 0. 先审计源文件，再决定路径（最重要的一步）

**输入质量决定上限，模型和算法只能逼近这个上限。** 同一份谱，96 DPI 导出图会让
任何 OMR 失败；PDF 里 219 DPI 的原始内嵌图则足以逐音转谱。

| 源文件 | 处理方式 |
|---|---|
| 扫描类 App 导出的 PDF（扫描全能王等） | **先抽内嵌原图**：`python scripts/extract_pdf.py <pdf>`；不要直接用同时导出的 JPG |
| JPG / PNG / TIFF | 直接做分辨率审计 |
| 出版方原始 PDF（矢量） | 优先；可无损转 MusicXML |
| 已有手工 `.mscz` / `.musicxml` 底稿 | 进入"校验模式"，用 `diff_scores.py` 对照，而不是从零转谱 |

### 质量闸门

用 `scripts/staff_spacing.ps1` 测五线线距（比折算 DPI 更可靠）：

| 线距 | 判定 | 处理 |
|---|---|---|
| ≥ 16 px | ✅ 可靠 | 走 v3 流程（§1） |
| 8–15 px | ⚠️ 边缘 | 走 v3 流程 + 每个和弦像素几何校验；密集段预期准确率下降 |
| < 8 px | ❌ 不可用 | 停止，要求 300–600 DPI 重扫或提供 PDF 原图 |

等效 DPI 参考：A4 页面高度像素数 ÷ 11.69。≥300 理想；200–300 可配合几何校验；
<150 基本不可用。**不要用插值放大伪造分辨率**——它不增加信息。

## 1. v3 主流程：草稿 → 代码校验 → 低置信审计

```
源文件 → [质量闸门] → [Audiveris 或 scan_draft.py 打草稿 MusicXML]
       → [自动校验关卡]（拍值 / 承接 / 小节线 / tie 配对 / 和声体检）
       → [置信度排序，AI 只审低置信项 + 抽检高置信项]
       → [修正合并] → [MuseScore 渲染 PDF/MP3] → [终检一次] → 交付
```

**分工原则：机器负责"看见"，代码负责"判断"，AI 只负责"裁决"。**

### 1.1 第一步：草稿（机器）

- **首选 Audiveris**（本机 `D:\Program Files\Audiveris\Audiveris.exe`）：
  `python scripts/run_omr.py` 或 `scripts/pipeline.py`。输出不可用时（密集和弦、
  手写覆盖）回退到自研扫描 `scripts/chord_scan.py` / `scan_draft.py` 全谱扫描。
- 草稿是**结构化 JSON + 置信度**存盘（`draft/*.json`），**不打印大段内容到对话**。
- 每个音/记号带置信度与证据坐标（x, y, 依据），供后续审计引用。

### 1.2 第二步：自动校验关卡（代码，建 XML 之前强制跑）

以下检查全部脚本化，**任何一项不过不允许生成 MusicXML**：

| 关卡 | 内容 | 实测价值 |
|---|---|---|
| `check_beats` | 每小节拍值 = 拍号（4/4 即 4.0）；弱起小节白名单 | 必备 |
| `check_accidental_carry` | 同小节同音名同八度：前有 ♯/♭、后无 ♮ → 后音继承变音；**穷举全曲**并报告每处印刷证据（音头左侧 N px 内无还原号） | 小天鹅舞曲一次找出全部 4 处承接错误 |
| `check_barlines` | 小节线=贯穿 5 线的连续竖线，与符干（接音头/符杠）区分 | 曾把符干误判为小节线 |
| `check_ties` | tie_start/tie_stop 配对、跨系统 tie 两侧音高一致 | 跨行延音线易漏 |
| `check_slurs` | slur 编号配对；弧线端点与音符对齐 | 弧线端点常内收 15–35px |
| `check_dynamics` | 力度字形识别（p/mp/mf/f）标记低置信，**须人工或用户终审** | mp 的 m 低分辨率下易糊成 p（小天鹅 m7 实错） |
| `harmony_check` | 和声体检（保留 v2 §3.1 流程） | 标记 ≠ 错误，转调段正常 |

### 1.3 第三步：AI 审计（只啃该啃的）

- **审计顺序**：校验关卡报的异常 → 置信度低于阈值的音符/记号 → 每系统抽检
  2–3 个高置信项（防止系统性偏差）→ 用户指名的位置。
- **审计输出**：每处裁决记入 `待人工核验清单`（格式见 §3.2）。
- **禁止重推导已知规则**：先查 §4 排印规则库；库里有的一直接用，没有的才测，
  测完**回写进规则库**。

## 2. Token 预算纪律（v3 强制）

1. **禁止 ASCII 像素图进上下文。** "有没有墨/有没有还原号/对不对齐"这类是非题，
   一律写 Python 函数返回 `True/False + 坐标`，只打印结论。ASCII 图仅限：
   真正歧义的字形裁决，且裁剪 ≤ 30×20 行、一次一张。
2. **禁止为每个问题写一次性探针脚本。** 工具收敛为参数化 CLI：
   `loc.py`（局部谱线+暗行）、`edges2.py`（格点掩蔽后上下缘）、
   `headfind.py`（音头连通域）、`scan_draft.py`（全谱扫描）。
   新需求 = 给现有脚本加参数，不是新建 `bars2.py`、`bars3.py`……
3. **看图节制**：只在数值证据互相矛盾时 Read 裁切图，裁剪紧密、必要时降分辨率；
   成品渲染图只在最后终检看一次（两页以内）。
4. **结构化数据落盘**，对话里只读汇总表和异常清单。禁止把整份 JSON dump 进上下文。
5. **机械批量验证**（逐音比对、逐小节拍值）可派便宜模型子代理，主对话只收结论。
6. 大工作量任务开始前先声明预算：预计几次扫描、几张图；超了就停下来汇报。

## 3. 校对与验收

- **有底稿时**：一律用 `diff_scores.py` 对照，不要凭感觉判断。
- **无底稿时**：抽样 3–5 个系统（慢速/中速/密集各取一），记录音高准确率；
  低于 99% 不允许批量推进。
- **每页留痕**：谱表数、线距、低置信清单、人工修改清单。

### 3.1 分歧仲裁：乐理优先，识别次之，人工兜底

（同 v2）底稿/候选谱与印刷谱分歧时：
1. **乐理排除**：`harmony_check.py` —— 内部冲突/无解决调外音/功能断裂 → 该版不成立；
   转调段调外音、半音 planing、离调解决 → 正常手法。
2. **两版都成立 → 按印刷谱为准**。
3. **乐理裁不了的 → 进"待人工核验清单"，不得擅自定稿。**

### 3.2 最终交付物

- 修订后 MusicXML + 排版 PDF + 参考 MP3
- 差异报告（含：源审计、方法、抽检表、**修正记录表**、遗留差异、假设、用户校对记录）
- **待人工核验清单**（必须交付），每条 6 字段：小节号、底稿记法、印刷谱读数、
  裁切图路径、乐理意见、建议动作。**没有这份清单不允许宣布完成。**
- 清单头部给出**优先处理子集**（影响音高/结构的条目）。

## 4. 排印规则库（逐谱回写，禁止重推导）

> 每完成一谱，把该版排印风格的新规则追加到这里。下次遇到同一出版社/同一版式的谱，
> 直接引用，不再用像素重新发现。

### 《小天鹅舞曲》张之良移植版（人音社风格铅版，2026-10 实测）

1. **加线栈规则**：A5/C6/E6… 的加线画到该和弦最高音为止；音头压在最高一条
   加线上 = 该加线音。据此可判 E6/D6 这类半槽差。
2. **音头判读**：音头纵向半径 ≈ 8 行（±8 行取中心）；压线的音头读数系统性
   偏低 ≈ +2px，需补偿。单音头 16–17px，二度双音合并 run 31–33px（两音头横向
   错开 ≈18px）。
3. **变音承接**：同小节同音名同八度，前 ♯ 后无 ♮ → 承接（本谱 31 个 ♯、0 个 ♮/♭）。
   承接错误会导致 MuseScore 自动补 ♮ —— **渲染输出里的"多余还原号"是承接审计的哨兵**。
4. **长连线括号式画法**：老式铅版用首尾"（ ）"代替长弧线（本谱仅开头 9 音一处）。
   判据：括号间无任何弧线（谱表上下扫描 + 底线粗细无差异）；配合跳音点 = 半连奏。
5. **连线弧端点**：可见端点比音符位置内收 15–35px；配对靠弧段扫描，不靠目视。
6. **符杠**：单杠厚 8–10px；三层杠 = 三十二分；低置符杠（谱表下方）是本版画法。
7. **休止符**：二分休止坐在第 3 线上，全休止挂在第 4 线下。
8. **跳音点偏高**：本版跳音点距音头可达 1.4 音位，且成对竖排圆点可能是奏法记号
   （非跳音），需按音位归属判断。
9. **谱面弯曲**：l0 随 x 漂移 10–28px/系统，必须逐 x 局部拟合，禁用全系统固定 y。
10. **力度字形**：小字号 + 低分辨率下 mp/mf 的第二个字母易糊，p/mp 区分须人工终审。

## 6. MuseScore 实测注意（本机 4.7.3 便携版）

- `-o *.pdf`、`-o *.mp3` 可用；**`-o *.png` 在输出路径含中文时返回码 2**——
  先导出到 ASCII 路径再复制。（v2 曾记录"png 不生成文件"，实为中文路径问题。）
- 显式 `<accidental>` 不要乱写：MuseScore 按调号+alter 自动标；承接变音只改
  `pitch/alter`，别写死 `<accidental>`。
- 分页/分行：每系统开头 `<print new-system="yes"/>`，换页处 `<print new-page="yes"/>`。
- 自带 `wind.reed.sheng`（笙）；无笙音源时 GM Reed Organ 代音色，仅用于校对音高节奏。
- 参考音频速度：原谱只印"快板"类文字时，需假设节拍器数值（如 ♩=132）并在报告中注明。

## 7. 常见坑

| 问题 | 原因 / 解决 |
|---|---|
| PDF 导出图和 PDF 内嵌图清晰度差很多 | 先 `extract_pdf.py`，用内嵌原图 |
| 音头粘成"8"字，读不准 | 三度叠置 + 低分辨率；像素测量 + 宽度剖面椭圆拟合，别靠肉眼 |
| 渲染结果冒出多余 ♮/♭ | 承接审计没跑——同小节同音高漏改 alter；跑 `check_accidental_carry` |
| 手写覆盖谱线 | 低置信区处理并人工确认；不要强行滤波 |
| 两份谱小节数不一致 | 多小节休止编码差异；用 `diff_scores.py` 内容对齐 |
| MuseScore CLI 不覆盖已有输出 / 中文路径 PNG 失败 | 先删旧文件；PNG 走 ASCII 路径 |
| PowerShell 变量大小写互相覆盖 | `$Lum` 与 `$lum` 是同一个变量，命名区分 |

## 8. 实测档案

- **《梦寻长安》**（2026-10，v2）：96 DPI JPG 不可用；PDF 内嵌图 219 DPI 可逐音转谱；
  5 和弦 15 音像素读数与人工底稿 15/15 一致；纯肉眼在低音叠置出过错。
- **《小天鹅舞曲》**（2026-10/11，v2 全流程 + v3 规则来源）：两页笙谱 38 小节 13 系统；
  全 AI 逐像素转谱成功但 token 消耗过大，直接催生 v3。产物与规则见 §4；
  用户校对：m7 力度 p→mp、开头括号式连线确认补记。
